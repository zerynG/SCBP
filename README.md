# SCBP

Система расчёта стоимости проекта (Django). Считает себестоимость и отпускную
цену по ресурсам (сотрудники, исполнители, подрядчики, оборудование) с учётом
производственного календаря, страховых взносов, наценки и НДС; формирует
документы КП и НМА в PDF/Excel/Word.

## Демо-доступ

База данных уже включена в архив (`db.sqlite3`) с демонстрационными данными —
создавать пользователя **не нужно**. Войдите по адресу http://127.0.0.1:8000/login/:

| Поле | Значение |
|------|----------|
| **Email** | `admin@demo.local` |
| **Пароль** | `Demo2026!` |

После входа откройте проект **«Демо-проект (все типы ресурсов)»** — в нём есть
ресурсы всех типов и все вариации расчёта. Документы (КП/НМА) — на странице
«Документы» проекта.

> Краткий старт: `python3 -m venv venv && source venv/bin/activate && pip install -r requirements.txt && python manage.py runserver`
> (миграции применять не обязательно — БД уже готова). Подробные шаги ниже.

## Локальный запуск: общие требования

- Python 3.11+ (рекомендуется актуальная LTS‑версия)
- Операционная система: Linux/Unix (например, Ubuntu, macOS) или Windows 10/11

Проект использует Django (`manage.py` в корне проекта) и по умолчанию работает с SQLite базой (`scbp/settings_local.py:31–36`), поэтому для локального запуска достаточно распаковать архив, установить зависимости и применить миграции.

## Локальный запуск на Linux/Unix (Ubuntu, macOS)

1. Распакуйте архив с проектом и перейдите в каталог проекта:
   ```bash
   cd IQNIX_SCBP
   ```

2. Создайте и активируйте виртуальное окружение:
   ```bash
   python3 -m venv venv
   source venv/bin/activate
   ```

3. Установите зависимости:
   ```bash
   pip install -r requirements.txt
   ```

4. Примените миграции базы данных (создаст `db.sqlite3`, если его ещё нет):
   ```bash
   python manage.py migrate
   ```

5. Создайте администратора (опционально, для входа в админку `/admin/`):
   ```bash
   python manage.py createsuperuser
   ```

6. Запустите дев‑сервер:
   ```bash
   python manage.py runserver
   ```

7. Откройте в браузере:
   - основной интерфейс: http://127.0.0.1:8000/
   - админ‑панель: http://127.0.0.1:8000/admin/

## Календарь рабочих дат (JSON)

- Файлы календаря лежат в каталоге: `calendar/calendar_2025.json`, `calendar/calendar_2026.json`.
- Формат:
  ```json
  {
    "year": 2025,
    "calendar": {
      "1": { "1": "holiday", "2": "holiday", "3": "work", "4": "work" },
      "2": { "1": "weekend", "2": "weekend", "3": "work" }
    }
  }
  ```
- Допустимые значения статуса дня: `work` (рабочий), `weekend` (выходной), `holiday` (праздничный/нерабочий).
- Использование: система читает JSON‑календарь и рассчитывает рабочие дни для планирования сроков и себестоимости, исключая выходные и праздники из расчётов.

## Как была решена проблема с рабочими датами

- Перешли на явный внешний JSON‑календарь по годам вместо зависимости от системных/локальных настроек дат.
- Логика расчёта использует статусы дней (`work` / `weekend` / `holiday`) из календаря, что устраняет неоднозначности и переносы.
- Исключили двойной учёт праздников и перенесённых выходных: в расчётах учитывается именно статус из календаря для конкретного дня.
- Добавлен фоллбек при отсутствии календаря на год, чтобы расчёты не падали и оставались предсказуемыми.

## Архитектура расчётов

Единый источник правды для всех формул — `mainboard/calculator.py`. Все view-функции (`project_manage`, `recalculate_project`, `generate_documents`, `_build_project_data`) используют этот модуль, поэтому числа на странице, в API и в документах **гарантированно совпадают**.

```
UI inputs
   │ (debounced AJAX-save)
   ▼
update_resource_override  ──┐
                            │
recalculate_project         │   ┌──────────────────────┐
                            ├──▶│  mainboard/          │
generate_documents          │   │  calculator.py       │
                            │   │  (Decimal pure fns)  │
_build_project_data         │   └──────────┬───────────┘
                            │              │
                            ▼              ▼
                       ProjectCost (DB)   JSON-ответ для JS
```

JS-зеркало живёт в `static/js/calculator.js` — те же формулы 1:1 на клиенте для оптимистичного live-превью. После каждого debounced AJAX-save сервер возвращает пересчитанный снимок `rows + totals`, и фронт догоняет его как «истину».

Ключевые свойства расчёта:

- **Decimal-арифметика** на бэке (округление до копеек — только на выходе).
- **Экономическая модель (РФ), всё настраивается на проекте, по умолчанию 0:**
  - **Страховые взносы** (`tax_rate`, %) — начисляются **только на ФОТ** (оклад штатных сотрудников) и входят в себестоимость. На исполнителей, подрядчиков и оборудование — **не начисляются**.
  - **Наценка / рентабельность** (`margin`, %) — надбавка к себестоимости ресурса. `NULL` у ресурса → берётся наценка проекта; `0` → строгий 0%; иначе — своё значение.
  - **НДС** (`vat_rate`, %) — начисляется **один раз на итоговую цену** (output), **не входит в прибыль**.
- Итоги: `Себестоимость = Σ cost` · `Цена без НДС = Σ final_cost` · `Прибыль = Цена без НДС − Себестоимость` · `НДС = Цена без НДС × vat_rate/100` · `Цена с НДС = Цена без НДС + НДС`.
- **Календарь рабочих дней** — JSON по годам в каталоге `calendar/`. Недоступные дни сотрудника (отпуск / другой проект) также учитываются по календарю.

### Настраиваемые параметры проекта (карточка «Финансовые показатели»)

| Поле | Где влияет | По умолчанию |
|---|---|---|
| Страховые взносы на ФОТ (%) | `cost = base × (1 + взносы/100)` — **только для сотрудников** | 0 |
| Наценка / рентабельность (%) | `final = cost × (1 + margin/100)` (когда у ресурса нет override) | 0 |
| НДС (%) | На итог проекта один раз: `НДС = ЦенаБезНДС × vat/100`, не входит в прибыль | 0 |
| Часов в дне (КЧЧ) | Отображение «Часы» у сотрудника = workDays × КЧЧ; для оборудования в режиме «рабочие часы» | 8 |
| Дней в месяце (fallback) | Сколько рабочих дней в месяце использовать, если JSON-календарь недоступен | 22 |
| База часов оборудования | Для `pricing_type='hour'`: `calendar` = days × 24, `working` = рабочих_дней × КЧЧ | calendar |

Карта формул с привязкой к функциям — в `formulas.xlsx` (генерируется `scripts/generate_formulas_excel.py`).
