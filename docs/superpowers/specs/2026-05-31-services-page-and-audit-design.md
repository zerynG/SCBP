# Страница «Реестр услуг» + ревизия расчётов

Дата: 2026-05-31

## Контекст

Услуги (`Service`) раньше управлялись вкладкой внутри «Каталога»
(`create_project.html`): только добавление и удаление. Задача — вынести их в
отдельную самостоятельную страницу по образцу страницы Ганта, плюс провести
ревизию формул и вёрстки.

## Что сделано

### 1. Отдельная страница услуг (полный CRUD)

- View `services_page` → `templates/services.html` (standalone, тёмный layout
  как `gantt.html`), доступ — карточка «Реестр услуг» на дашборде.
- Бэкенд-эндпоинты:
  - `services_page` (`/services/`) — список со счётчиком использования.
  - `add_service` (`/services/add/`) — добавление (AJAX).
  - `edit_service` (`/services/<id>/edit/`) — редактирование названия/описания,
    флага активности, а также быстрый тумблер (`action=toggle_active`).
  - `delete_service` (`/services/delete/<id>/`) — удаление; связь ресурсов
    обнуляется (FK `SET_NULL`), фронт предупреждает, если услуга используется.
  - `services_api` (`/services/api/`) — JSON активных услуг (переехал с `/services/`).
- Счётчик использования: `ProjectResourceOverride.service` →
  `usage_resources` (ресурсов) и `usage_projects` (проектов) через `annotate`.
- Старая вкладка «Услуги» из «Каталога» удалена полностью.

### 2. Ревизия (аудит)

- **Сверка `calculator.js` ↔ `calculator.py`:** примитивы (`applyTaxAndMargin`,
  базовые расчёты по типам) — зеркало 1:1; агрегаты в `project_manage.js`
  (`final_price = Σ final_cost`, `base_cost = Σ cost`, `net_profit = final − base`)
  совпадают с Python. Расхождений нет — правок не потребовалось.
- **Семантика `net_profit`:** обнаружено расхождение между кодом и
  академической мат-моделью в дипломе. Решение — см. ниже.
- **Вёрстка:** прогон в браузере (дашборд, услуги, проект) — страницы
  рендерятся корректно, KPI согласованы. Критичных проблем не найдено.

## Решение по `net_profit` (зафиксировано)

Диплом описывал две интерпретации итоговой цены. **Оставлена интерпретация 1:
налог применяется ровно один раз** (на уровне строки ресурса):

```
cost       = base_no_tax · (1 + tax/100)
final_cost = cost · (1 + margin/100)
base_cost  = Σ cost
final_price = Σ final_cost
net_profit = final_price − base_cost = Σ cost · margin/100
```

Обоснование: это текущее, согласованное между Python и JS поведение;
двойное налогообложение (`P_final = C_margin · (1+tax)`) сам диплом помечает как
ошибочный паттерн. Прод-числа НЕ менялись. Документ мат-модели приведён в
соответствие с реализацией (`docs/diploma/...-math-model.md`).

## Открытые вопросы (на согласование с заказчиком)

- Подтвердить, что «прибыль» = сумма маржи (а `base_cost` включает налог) —
  устраивает бизнес. Если ожидается «прибыль = цена − себестоимость без налога»,
  потребуется отдельная правка определения.
- Оборудование `pricing='hour'` с базой `calendar` тарифицируется 24 ч/сутки за
  весь календарный период — поведение настраивается на проекте
  (`equipment_hour_basis`), оставлено по умолчанию для совместимости.
