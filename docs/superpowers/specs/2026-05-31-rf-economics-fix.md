# Корректная экономическая модель расчёта (РФ)

Дата: 2026-05-31

## Проблема

Исходные формулы (доставшиеся от плохого ТЗ) применяли **единый `tax_rate`**
ко всем ресурсам как наценку на себестоимость: `cost = base × (1 + tax/100)`,
затем `final = cost × (1 + margin/100)`. Это экономически некорректно для РФ.

Глубокое исследование (22 источника: ФНС, Минтруд/КонсультантПлюс, kontur,
glavkniga, garant; 23/25 фактов подтверждены состязательной проверкой) показало:

- **НДС** — это надбавка на **отпускную цену** (output), а не на себестоимость;
  начисляется поверх цены продажи и перекладывается на покупателя (ФНС).
  С 01.01.2026 базовая ставка — **22%** (не 20%).
- **Страховые взносы (~30%, для IT-аккредитации 15%)** — нагрузка работодателя
  **сверх оклада**, начисляются **только на ФОТ**, входят в себестоимость.
- **НДФЛ** удерживается **из** оклада, не добавляется сверху (двойного счёта нет).
- **Единый `tax_rate` на все ресурсы — некорректен**: взносы (на ФОТ) ≠ НДС
  (на цену) ≠ НПД у самозанятого ≠ налоги юрлица-подрядчика.
- **Маржа** считается от цены, **наценка** — от себестоимости; их нельзя смешивать.

## Решение (реализовано)

Единый `tax_rate` разделён на **два настраиваемых параметра проекта**
(по умолчанию 0 — ничего не начисляется, пока не задано):

| Параметр | Поле | База начисления |
|---|---|---|
| Страховые взносы на ФОТ | `Project.tax_rate` | только оклад **сотрудников** (employee) |
| НДС | `Project.vat_rate` (новое) | итоговая цена проекта, один раз (output) |
| Наценка / рентабельность | `Project.margin` | себестоимость ресурса |

Формулы:

```
# на ресурс
cost  = base × (1 + взносы/100)   # взносы только для employee, иначе ×1
final = cost × (1 + наценка/100)

# на проект
Себестоимость  = Σ cost
Цена без НДС    = Σ final
Прибыль         = Цена без НДС − Себестоимость        # НДС в прибыль НЕ входит
НДС             = Цена без НДС × vat_rate/100
Цена с НДС       = Цена без НДС + НДС
```

## Затронутые файлы

- `mainboard/models.py` — поле `vat_rate`; переименованы verbose_name
  (`tax_rate`→«Страховые взносы на ФОТ», `margin`→«Наценка/рентабельность»).
- `mainboard/migrations/0010_project_vat_rate.py`.
- `mainboard/calculator.py` — взносы только на employee; НДС в итогах
  (`vat_rate`, `vat_amount`, `price_with_vat`); `serialize_totals`.
- `mainboard/views.py` — парсинг `vat_rate`; проброс НДС в контекст и в документы.
- `static/js/project_manage.js` — взносы только для employee-строк; НДС-карточки
  (показ при vat>0); пересчёт при изменении НДС.
- `templates/project_manage.html` — поле НДС, KPI «Цена без НДС / НДС / Цена с НДС»,
  переименование меток и колонки «Наценка %».
- `mainboard/tests.py` — `RFEconomicsTests` (взносы только на ФОТ; НДС на output;
  vat=0 по умолчанию). Всего 39 тестов, зелёные.

## Проверка

- 39 unit-тестов; согласованность итогов проверена: `base + profit == final`,
  `final + НДС == price_with_vat`, `НДС == final × ставка/100`.
- Браузер: финансовая карточка, появление НДС-карточек при vat>0, live-пересчёт.

## Допущения (настраиваемые, легко изменить)

- Взносы начисляются только на штатных сотрудников. Если для ГПХ-физлиц нужны
  взносы — закладываются в ставку исполнителя (или добавляется per-resource флаг).
- Ставки НДС/взносов не зашиты — параметры проекта (НДС 22% с 2026, IT-льгота 15%
  и т.п. задаются вручную).
- Входной НДС подрядчиков-юрлиц к вычету и амортизация оборудования — вне модели
  (открытые вопросы из исследования).
